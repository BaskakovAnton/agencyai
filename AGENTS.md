## 7. Соглашения по работе
- **Правило тестов (закон проекта, с 16.11.2026):** на **всё**, что внедряется в код или данные,
  сначала пишутся тесты (красные), затем реализация; внедрять только когда `bun test` полностью зелёный.
  Без тестов не внедряется ничего. Порядок: план → тесты → реализация → зелёные → сборка/пуш.
- **Отвечать только по-русски** (правило владельца от 24.11.2026): все ответы, планы, отчёты, сообщения коммитов, документация и подписи интерфейса — на русском языке. Исключения только для технических идентификаторов: имена файлов, команд, токенов, моделей и URL.
- Отвечать кратко и по делу; в конце — конкретное предложение следующего шага.
- После осмысленного результата: `git add -A && git commit` (сообщения в стиле `docs:`, `feat:`, `chore:`) и `git push` в `origin main`.
- Секреты, токены и приватные данные не коммитить: репозиторий **публичный**, всё уходит в открытый доступ.
- Для личных/некоммитимых заметок использовать `AGENTS.local.md` (тоже подхватывается харнессом).
- В конце значимой работы — дописать строку в «Журнал» **в конец таблицы** (не вставлять в середину) и обновить дату в шапке.
- **Правило документов (28.11.2026, решение OD-1=B).** В Git идут спецификации (`docs/specifications/`), дизайн-спецификации (`docs/design/`) и релизные отчёты (`docs/reports/*release*`). Черновики discovery, review-, preflight- и промежуточные implementation-отчёты остаются **локальными** и в репозиторий не добавляются: репозиторий публичный, а черновики содержат рабочие формулировки. Список локальных документов — в `docs/design/interface-roadmap.md`.
