- **Суть:** интерактивный прототип регламента приёмной депутата — цикл «житель → депутат-диспетчер → подрядчик», «Регламент · раздел 8». Mobile-first, светлая/тёмная тема, всё inline (CSS+JS), без внешних зависимостей.
- **Страницы:** `index.html` (65 KB, лендинг + список 37 ситуаций + sheet-степпер + dock-навигация), `process.html` (43 KB, тот же список с группами 8.1–8.4 + плеер в модалке), `player.html` (35 KB, свимлейн-плеер: автопрокрутка, скорость, прогресс, клавиатура), `matrix.html` (53 KB, матрица «роль × узел», 2 вида, панель деталей, кнопка «Экспорт JSON»).
- **Модель данных (в JS-константах внутри страниц):**
  - 7 ролей: `resident` Житель, `deputy` Депутат-диспетчер, `assistant` Помощник, `contractor` Подрядчик/УК, `system` Система (авто), `observer` Наблюдатель (админ/прокурор), `auditor` Аудитор (только в матрице).
  - 30 узлов `U1…U30` в 6 группах (приём, исполнение, управление, закрытие, просмотр, особые); уровень доступа роли: `✓ может / ⊂ только в своём / ! при условии / ✕ запрещено / — не участвует`, у каждого — пояснение и привязка к ситуациям.
  - 37 ситуаций `С1…С37`; разделы: 8.1 До принятия = 8, 8.2 В работе = 20, 8.3 Подрядчики = 5, 8.4 Отчётность = 4; приоритеты: urgent 4, normal 18, routine 1, none 14; ≈109 шагов.
  - Формат шага расходится: `player.html` — `[lane, title, detail]` (самый полный, включает лейн жителя), `index/process.html` — `{lane, text}`.
- **Домен (содержание):** SLA как состояние (пауза/возобновление — погода, нет доступа, согласования, финансы; узлы U14/U15), эскалация (U16), переадресация (U17), массовая проблема → один issue (U18), аварии С9–С10 вне очереди. Право/контроль: доступ к ПД ФЗ-152 (U24), append-only аудит (U25), конфликт интересов «депутат — подрядчик» (U27), запрет удаления + архив 5 лет ФЗ-59 (U30), запрос прокуратуры (С37). Ограничения ролей: подрядчик не проверяет себя и не закрывает; помощник не закрывает спорные; авто-закрытие через 7 дней молчания.
