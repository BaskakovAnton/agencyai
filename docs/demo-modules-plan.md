# План: два демо-модуля (дашборд когорт и чат-плеер)

## Что делаем

Два новых экрана в том же SPA-демо (навигация по хэшу: `#dashboard`, `#chat`), поверх нашей модели:
30 заявок, 30 узлов, ситуации, роли, SLA. Отдельный файл данных не нужен — данные уже в модели
(файл «agencyai · модель процессов.txt» в системе отсутствует; при необходимости добавим экспорт JSON).

## Модуль 1 — «Шкала времени и когорты»

- **Ядро** `src/core/analytics.ts`: группировка по узлу и когорте срочности, текст тултипа, фильтры.
- **Когорты:** 🔴 авария / экстренно · 🟡 неотложное · 🟢 обычное / сезонное (+ «вне SLA» серым).
- **График:** Chart.js stacked bar, ось X — 30 узлов (U1…U30), ось Y — количество заявок.
- **Тултип:** внешний HTML-тултип (Chart.js `external`) — «Узел U7 · Передача подрядчику: 3 заявки
  (1 аварийная, 1 неотложная, 1 обычная)» — так его можно проверить и глазами, и e2e-тестом.
- **Интерактив:** клик по столбцу фильтрует список заявок до этого узла.
- **Фильтры слева:** роль оператора (заявка показывается, если роль может действовать на её узле —
  переиспользуем `roleAccess`), когорта (только аварийные и т.д.), сброс.
- **Список справа:** заявки, попавшие под фильтры, с узлом, приоритетом и SLA.

## Модуль 2 — «Переписка по ролям»

- **Сценарий** `src/web/chat-scenario.ts`: заявка **З-015 «Разбита дверь подъезда»**, маршрут
  U1 → U6 → U7 → U19, роли: Житель → Депутат-диспетчер → Подрядчик → Житель, тексты сообщений по ТЗ.
- **Стейт-машина** `src/web/chat.ts` (чистые функции): текущий шаг, активная роль из узла,
  ручное переключение роли («Сменить роль (симуляция)»), следующий/предыдущий узел, накопление сообщений.
- **UI:** три панели — список 30 заявок (выбрана З-015) · чат с цветом и аватаром роли · паспорт заявки
  со степпером (пройденные серые, текущий акцентный, будущие бледные) и контекстными карточками
  (SLA с остатком времени, текущий подрядчик). Кнопка «Следующий узел» и авто-плеер.

## Технически

- Зависимости: `chart.js` (в бандл), `@playwright/test` (dev). Степпер и карточки — на CSS, без тяжёлого Mermaid.
- Роутер `src/web/router.ts`, страницы рендерятся в один `demo/app.js`.
- e2e: `playwright.config.ts` + локальный статик-сервер `scripts/serve-demo.ts` (Bun.serve),
  спеки `e2e/dashboard.spec.ts` и `e2e/chat.spec.ts`; CI — `.github/workflows/e2e.yml`
  (setup-bun → bun install → bun test → playwright install --with-deps chromium → playwright test).

## Проверяем тестами (до реализации)

1. `cohortsByNode`: 30 узлов, счётчики по когортам и общий итог.
2. `tooltipFor`: точный текст с правильными формами («1 заявка», «3 заявки», «5 заявок»).
3. `applyFilters`: по когорте, по узлу, по роли (роль фильтрует заявки по правам на текущем узле), комбинация.
4. Чат: маршрут U1→U6→U7→U19, роли по узлам, накопление сообщений, клампы на границах, ручное переключение роли.
5. SLA-карточка чата берёт состояние из нашей модели (не выдуманные числа).
6. e2e (Playwright): дашборд — загрузка, тултип при наведении, фильтр по когорте и по клику;
   чат — старт на U1 как «Житель», «Следующий узел» меняет роль и добавляет сообщения, у U7 появляется SLA-карточка.
