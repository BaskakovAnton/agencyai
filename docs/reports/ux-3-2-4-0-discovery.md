Достоверность: **FACT** (код/тест/наблюдение), **INFERENCE** (вывод), **UNKNOWN** (не проверено). Реализация не выполнялась.

## 1. Executive Summary

**Статус: READY WITH LIMITATIONS.** Реестр технически поддерживает больше, чем показывает интерфейс: URL-контракт принимает «view» (семь значений) и «department», но пользовательских контролов для них нет (FACT), активные фильтры нигде не отображаются, а единственный текст пустого состояния один для пяти разных причин.

**Минимально необходимое для UX-3.2.4:** панель активных фильтров (чипы) и два селекта — «Представление» (view) и «Подразделение» (department). Архитектурно всё готово: контролам нужно только писать в существующий filtersHash и обновлять URL через paintBody(push).

**Главная проблема, не решаемая в этом этапе:** мобильный реестр (таблица 902 px при экране 390 px, тулбар 370 px высотой, 17 нажатий Tab до первой строки) — требует отдельного решения владельца.

## 5. Подразделения (FACT)

- Параметр department, формат DEP-* или none, валидация DEPARTMENT_ID (incidents.ts:57), фильтрация matchesDepartment (incidents-view-filter.ts:50).
- Атрибуция — текущая: org.accountableOf(incidentId); исторической нет (F5).
- department=none → 3 обращения из 28 на 02.01.2026 (проба).
- Неизвестный код → фильтр игнорируется, показываются все (departmentFilterActive, строка 44).
- DEP-ARCHIVE — реальное подразделение без обращений: ссылка ведёт в честное пустое состояние (проба).
- UI-контрола нет: [data-filter-department] = 0.

## 6. Поиск q (FACT)

- Поле: incidents-html.ts:82 (input type=search, data-search), обработчик incidents-view.ts:51-53.
- Ищет по склейке полей matches (incidents.ts:105): id, title, address, reporter, channel, situation; нормализация trim().toLowerCase() — поиск регистронезависимый по подстроке.
- Сочетается с view, department и at (последовательное применение в buildRows).
- URL: replaceState на каждое нажатие (историю не засоряет), значение восстанавливается после reload (e2e ux32 E, ux3233 F).

## 7. Историческая дата at (FACT)

- resolveDay (day-window.ts): пустой или некорректный at → последний доступный день как значение по умолчанию; дата вне окна возвращается как есть со статусом outside — молчаливой подмены нет.
- renderOutsideWindow даёт единое состояние на всех экранах, таблицы и счётчика нет; ссылка ведёт к ближайшей доступной дате.
- Дата сохраняется при всех переходах контракта (e2e ux322, ux3231, ux3233 G).

## 8. URL-контракт (FACT)

Поддерживаются at, view, department, q, priority, sla, node, sort (реестр) и period (обзор), а также legacy review=pending — только чтение, канонизируется в view=review. Неизвестные значения игнорируются; filtersHash пишет канонический набор и никогда review. Дискретные изменения — pushState, ввод поиска — replaceState; reload и Back/Forward восстанавливают состояние интерфейса, а не только адрес (подтверждено e2e).

## 12. Предлагаемый UX-контракт (минимальный, НЕ реализован)

**A. Панель активных фильтров (чипы), data-filter-chips** — под тулбаром. Показывает только непустые фильтры: view, department, q, priority, sla, node и дату, если она не по умолчанию. Каждый чип содержит название, значение и кнопку «×» (обычный button, вложенных ссылок нет); «×» снимает только этот фильтр, остальные сохраняются. Если фильтров нет — панель не отображается. URL: изменение чипа → filtersHash → pushState, at не теряется. Мобильные: горизонтальная прокрутка строки чипов, высота не ниже 32 px. Критерии приёмки: после перехода из KPI чип показывает активное представление; «×» возвращает полный список с сохранением at; reload, Back и Forward сохраняют соответствие чипов и URL; чипы доступны с клавиатуры.

**B. Селект «Представление»** — в тулбаре рядом с «Подтверждение» (судьба второго — решение владельца). Значения: все, активные, требуют внимания, просроченные, на паузе, ждут подтверждения, без ответственного. Пишет канонический view; при «все» параметр из URL исчезает. Пустое состояние — существующее, с текстом по причине.

**C. Селект «Подразделение»** — в тулбаре. Значения: все, реальные DEP-* из справочника, без ответственного (department=none). Пишет department. Подпись о текущей атрибуции (F5) в блоке подсказки.

Все три элемента используют существующие функции (filtersHash, parseFilters, buildRows): новый URL-контракт и второй механизм состояния не создаются.
