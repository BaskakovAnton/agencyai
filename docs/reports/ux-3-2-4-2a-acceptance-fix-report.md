## 3. Аудит unassigned

Исходный предикат (до корректировки, incidents-view-filter.ts:35): `org.accountableOf(incident.id) === null` — возвращал true для всех обращений без ответственного, включая завершённые, потому что режим обрабатывался до проверки завершённости и не учитывал нормализацию undefined к null.

Ответы независимого аудита: 1) accountableOf возвращает undefined для обращения без активного ответственного; 2) да, undefined возможен; 3) null возможен только после явной нормализации; 4) нормализация есть в matchesDepartment (строка 52, через ?? null); 5) активность определяется историческим статусом на дату через isCompletedOn/lifecycleStatusOn; 6) используется исторический статус на дату среза (не текущий); 7) порядок в buildRows: видимость на дату, затем matchesView, затем matchesDepartment, затем поиск и сортировка; 8) прежний предикат включал завершённые, потому что стоял раньше проверки завершённости; 9) department=none не требует активности и потому даёт более широкое множество.

Исправление (incidents-view-filter.ts:35-40): ветка unassigned проверяет и активность, и отсутствие ответственного: `!isCompletedOn(org, incident.id, day) && org !== undefined && (org.accountableOf(incident.id) ?? null) === null`. Новый механизм активности не создавался — переиспользован isCompletedOn (тот же, что в блоке active). department=none, accountableOf и доменная модель не изменялись.
