## 4. Реализация по блокам

- **A.** Предикат view=unassigned исправлен на `(org.accountableOf(id) ?? null) === null` (incidents-view-filter.ts:35–37). Фактическая семантика — совпадает  department=none (единый сценарий DEC-UX-324-03), а не «активные без ответственного»: режим определён до проверки завершённости. Отражено в тестах и в разделе 14.
- **B.** Селект «Подтверждение» удалён; добавлены селект «Представление» (все, активные, требуют внимания, просроченные (активные), на паузе, ждут подтверждения) и селект «Подразделение» («все подразделения» + справочник + «без ответственного»). Список подразделений формируется из org.directory.departments, чисел в списке нет. Обработчики пишут view и department через существующий paintBody(push).
- **C.** Новый модуль incidents-chips.ts: filterChips, renderFilterChips, filtersWithout. Чипы появляются только для непустых параметров, sort не показывается, чип даты — только когда дата отличается от последней доступной. Снятие чипа меняет один параметр, синхронизирует контролы и перерисовывает живую область счётчиком.
- **D.** Новый модуль incidents-empty.ts: emptyReasonFor/emptyStateFor/renderEmptyIncidents. Различаются 6 причин внутри таблицы (no-data, search, view, department, unassigned, combination) и отдельное состояние outside (UX-3.2.2). Действие снимает только нужный фильтр; для комбинации — «Сбросить фильтры».
- **E.** Новый модуль incidents-notice.ts: пояснение F5 показывается только при исторической дате И непустом фильтре подразделения (включая none), не появляется для view, q, sla, priority, node.
- **F.** CSS панели чипов вынесен в отдельные классы incident-chips/incident-chip (классы .chip/.chips уже заняты другими экранами), добавлена адаптация строки фильтров: на <768 px селекты по два в ряд, поиск и счётчик на всю ширину, чипы прокручиваются по горизонтали, кнопки не меньше 32 px.

## 5. Исправление unassigned

Причина: сравнение результата accountableOf с null, тогда как функция возвращает undefined — режим всегда давал пустой список (02.01: 0 вместо 3 обращений). Изменение: нормализация `?? null`, та же, что в matchesDepartment. До/после: 22.12 — 0 → 1 (З-005), 02.01 — 0 → 3 (З-005, З-016, З-027), 13.01 — 0 → 3. Другие режимы не изменились (02.01: active 27, attention 14, overdue 14, paused 0, review 6, all 28) — подтверждено тестом A5. Бизнес-семантика не менялась: модель ответственных и историческая атрибуция не затронуты.

Фактическое поведение приложения корректно, ошибка была в ожидании проверки, а не в коде.
