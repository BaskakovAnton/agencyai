## 1. Где отображается исторический индикатор

| Место | Что показывается |

| Реестр (`#incidents`) | тот же индикатор под тулбаром; при смене дня экран перерисовывается целиком, поэтому индикатор обновляется |

Правило одно для всех экранов: `isHistoricalDay(day, days)` в `src/web/historical.ts` (текущая дата модели — последний день среза). На текущей дате индикатор не выводится; независимых правил в компонентах нет.

## 2. Как гарантируется порядок событий

Исследованы: append-only журнал (`events.ts`), записи жизненного цикла (`completion-types.ts`), репозиторий (`org-repository.ts`), Snapshot (`analytics/snapshot.ts`), Flow (`analytics/flow.ts`), статус карточки (`org-integration.ts`).

**Гарантия уже есть, реализацию не меняли:**

1. Записи добавляются только в конец: `records: [...input.lifecycle.records, record]`; события — только через `appendEvents`.
2. Репозиторий отдаёт массивы как есть — сортировки записей и событий нигде нет (проверено поиском по `src/core/org`, `src/data/org-repository.ts`, `src/core/analytics`).
3. `lifecycleStatusOn` проигрывает записи в порядке массива, отбрасывая те, у которых день позже среза. При одинаковом timestamp побеждает **последняя запись по порядку записи**.
4. Счётчики Flow и Snapshot от порядка не зависят — порядок важен только для итогового статуса, и он детерминирован.

## 7. Оставшиеся ограничения

1. «Текущая дата» — последний день модели, а не системная: демо-история статична.
2. Все события одного дня имеют одинаковый timestamp (12:00): порядок определяется порядком записи, а не разрешением времени; вводить ручной выбор времени не стали (по условию).
3. Индикатор исторического режима есть на Dashboard, в реестре и в карточке; на хронологии и в переписке он не добавлялся (не требовалось заданием).
4. Тач-цели меньше рекомендованных (2837 замеров) — существовавшая особенность компактных контролов.
5. `src/web/incident-html.ts` вплотную к лимиту 200 строк — при следующей правке потребуется разделение.
