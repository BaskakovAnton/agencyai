# Ручной чек-лист терминальной модели

Проверка команд оператора на живом прогоне. Seed фиксирован (`--seed 7`), поэтому результаты повторяемы.

## 0. Подготовка

```bash
cd /c/Users/Pavel/Desktop/agencyai
bun --version            # 1.4.4
bun test                 # ожидаем: 18 pass, 0 fail
```

## 1. Один прогон без интерактива (дым-тест)

```bash
bun run src/cli/main.ts --seed 7 --script "graph;list;show 5;forward 5;forward 5;back 5;move 5 U7;move 5 U20;sweep;report;save;quit"
```

> Пайп команд в stdin (`printf 'list\n' | bun run src/cli/main.ts`) **не поддерживается**: интерактивный
> режим требует настоящий терминал и теперь честно сообщает об этом вместо зависания. Для пакетного
> прогона используйте `--script`.

## 2. Интерактивная сессия

```bash
bun run src/cli/main.ts --seed 7
```

Дальше по шагам (ожидаемый результат — то, что должно появиться на экране):

| Шаг | Команда | Ожидаемый результат |
|---|---|---|
| 1 | `help` | список команд оператора |
| 2 | `graph` | 30 узлов, 6 групп, U1…U30 |
| 3 | `node U7` | «Передача подрядчику [Исполнение]», соседи U6/U8, доступ 7 ролей |
| 4 | `list` | 30 заявок, колонки ровные, приоритеты: авария → неотложное → сезонное |
| 5 | `show 5` | З-005 на **U5**, история пуста |
| 6 | `forward 5` | З-005 на **U6**, шаг 1: U5 → U6 |
| 7 | `forward 5` | З-005 на **U7**, шаг 2: U6 → U7 |
| 8 | `back 5` | З-005 на **U6**, шаг 3: U7 → U6 |
| 9 | `move 5 U7` | З-005 на **U7**, шаг 4: «переход к соседнему узлу» |
| 10 | `move 5 U20` | **отказ**: «узел U20 не соседний для U7 (соседи: U6, U8)» |
| 11 | `back 5` | З-005 на **U6**, шаг 5 |
| 12 | `sweep` | массовый прогон: «сдвинуто N заявок», список обновился |
| 13 | `show 5` | З-005 на **U9** (после sweep ушла на два узла вперёд) |
| 14 | `report` | отчёт: заявок, переходов, по приоритетам, по группам, где стоят |
| 15 | `save` | «сохранение: отчёт + финальное состояние…» и два пути в `reports/` |
| 16 | `quit` | выход; напоминание, что без `save` файлы не пишутся |

## 3. Граничные случаи (все — корректные отказы)

| Команда | Ожидаемый результат |
|---|---|
| `back 1` | `отказ: З-001: узел U1 — начало процесса` |
| `forward 30` | `отказ: З-030: узел U30 — конец процесса` |
| `node U99` | `неизвестный узел: U99` |
| `show 999` | `заявка не найдена: 999` |
| `move 5 U20` | `отказ: узел U20 не соседний… (соседи: …)` |
| `абракадабра` | `не понял команду: "абракадабра" — help для списка` |

Ссылки на заявку равнозначны: `5`, `З-5`, `z-5`, `Z-005`.

## 3.1. Развилки (рандомные решения)

Терминал собирает граф **с развилками**, поэтому часть переходов выбирается по весам.

| Команда | Ожидаемый результат |
|---|---|
| `node U12` | `развилка: U13 40% — результат не принят — возврат на переделку; U19 60% — результат принят — ответ жителю` |
| `node U9` | три варианта: U6 45%, U16 30%, U10 25% |
| `forward 12` несколько раз | узел будет прыгать между U13 и U19 (вес 60% против 40%) |

Развилки: U4 → U5/U6, U9 → U6/U16/U10, U12 → U13/U19, U13 → U10/U6/U14.
Обратный ход симметричен: если заявка пришла на U19 из U12, то `back` вернёт её на U12.

## 4. Что посмотреть в файлах

```bash
ls -la reports/
cat reports/report-*.md | head -20
```

- `report-*.md` — человекочитаемая сводка (единственный текстовый отчёт);
- `final-state-*.json` — полное состояние: узлы, заявки, история переходов, лог сессии.

Больше ничего на диск не пишется: состояние живёт в оперативной памяти.
