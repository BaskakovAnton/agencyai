# План: роли в переходах (права доступа)

## Зачем

Права ролей уже лежат в данных узлов (`✓ allow / ⊂ subset / ! conditional / ✕ deny / — na`),
но движок их не проверяет: любая роль может сдвинуть заявку на любой узел.
Правило проекта: сначала тесты, потом внедрение.

## Правила доступа

- `allow` — роль может действовать на узле без оговорок;
- `subset` — может, но только в своём (житель — своё обращение, подрядчик — свои заявки);
- `conditional` — может при условии (обоснование, журнал, доступ по необходимости);
- `deny` и `na` — **не может**.

Проверка выполняется по **узлу назначения**: переход означает, что роль выполняет шаг на этом узле.
Возврат назад (`back`) — это откат, а не новое действие, поэтому правами не ограничивается.

Следствие, важное для модели: **U30 «Удаление» запрещён всем ролям** (`deny` × 7),
поэтому ни один процесс не доходит до удаления — заявки архивируются на U29.

## Изменения

- `src/core/roles.ts` — `roleAccess(graph, nodeId, role)` → `{ level, allowed, caveat }`, `allowedRoles`.
- `src/core/navigation.ts` — `allowedNext` (варианты, доступные роли), `moveToNodeAs`,
  `moveForwardAs` (взвешенный выбор только среди доступных), `isArchived`.
- `src/types.ts` — в `Session` добавляется `role` (роль оператора).
- `src/cli` — команда `role <id>`, переходы проверяются правами; `sweep` идёт от роли `system`.
- `src/web` — переключатель роли оператора, права на кнопках, отказ с объяснением.
- `src/core/report.ts` — «дошло до конца (архив)» учитывает блокировку по правам.

## Проверяем тестами

1. Уровни доступа читаются из данных (U19: deputy allow, assistant conditional, contractor na).
2. `allowed` = allow/subset/conditional; deny/na запрещены.
3. `allowedRoles(U25)` = system, observer, auditor.
4. `moveToNodeAs`: подрядчика не пускают на U19, депутата пускают.
5. `moveForwardAs` фильтрует ветки: у подрядчика на U9 остаётся только U10.
6. Тупик: у U29 нет доступных переходов ни для одной роли → заявка в архиве.
7. U30 недостижим ни для одной из 7 ролей.
8. CLI: `role contractor` меняет роль и запрещает переход на U19 с внятным отказом.
9. Web: страница показывает роль оператора и блокирует недоступный переход.
