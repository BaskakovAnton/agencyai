# Регламент релиза (D2)

Каждый пакет сдаётся по одному чек-листу. Пункты обязательны, если не указано иное.

## 1. До кода

- [ ] Требование сформулировано, границы ясны, решение владельца получено.
- [ ] Написан красный тест и зафиксировано его падение по ожидаемой причине.

## 2. Реализация

- [ ] Изменения минимальны и не расширяют область.
- [ ] `src/core` и `src/data` менялись только с тестами.
- [ ] URL-контракт не расширялся, новые параметры не вводились.
- [ ] Файлы не выше 200 строк (цель — до 170); у лимита модуль выносится сразу.
- [ ] «Нет данных» показано текстом, выдуманных значений нет.

## 3. Локальные гейты

| Команда | Что проверяет |
|---|---|
| `bun run typecheck` | типы |
| `bun test` | unit |
| `bun run coverage:gate` | покрытие домена ≥ 92% строк / 88% функций |
| `bun run size:budget` | app.js ≤ 180 КБ, demo ≤ 260 КБ |
| `bun run build:demo` | сборка артефакта |
| `bun run verify:demo` | закоммиченный demo совпадает со сборкой |
| `bunx playwright test --project=chromium` | полный e2e |
| `bunx playwright test --project=firefox --project=webkit` | кросс-браузерный базовый набор |
| `bun run audit` | аудит: нарушений 0 |

## 4. Публикация

- [ ] Коммит одним смысловым изменением, сообщение на русском.
- [ ] `git push origin main`.
- [ ] CI: задача e2e и живая проверка — success.
- [ ] Pages: сборка на коммите выпуска.
- [ ] Живая проверка: тема, бренд, шесть экранов, 0 ошибок консоли.

## 5. После

- [ ] Строка в `docs/journal.md` с числами и коммитом.
- [ ] Обновлён статус в плане или отчёте.
- [ ] Лишние локальные серверы остановлены.

## 6. Частые ошибки

| Ошибка | Как избежать |
|---|---|
| `bun test` в одной команде с `build:demo` | тест синхронности demo может поймать запись файла — запускать раздельно |
| Абсолютные пороги геометрии | шрифты платформ разные: сравнивать доли от экрана |
| Забыли `build:demo` | e2e идёт по собранному `demo/` |
| Пуш без пересборки | гейт `verify:demo` в CI поймает, но лучше локально |
