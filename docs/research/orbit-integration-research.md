## 1. Наши ограничения (FACT)

| Ограничение | Где проверено | Значение для внедрения |
|---|---|---|
| Нет runtime-зависимостей | `package.json`: `dependencies: {}`, в dev — только playwright, types, axe-core | Orbit стал бы **первой** рантайм-зависимостью |
| Сборка — одна точка входа без splitting | `scripts/build-web.ts`: `entrypoints: [src/web/main.ts]`, `format: esm`, без `splitting` | всё импортируемое попадает в один `app.js` |
| Бюджет размера | `scripts/size-budget.ts`: app.js ≤ 180 КБ, demo ≤ 260 КБ | новые файлы обязаны вписаться |
| Бандл самодостаточен | `tests/web.test.ts`: запрещены `from "http…"`, `import("http…"`, `fetch("http…`, bare-импорты | **CDN-подключение внутри SPA запрещено нашим тестом** |
| Лимит файлов ≤ 200 строк (цель 170) | правило проекта | новые модули обязаны вписаться |
| Тесты до реализации, axe без critical/serious, цвет — второй канал | AGENTS §7, `e2e/a11y.spec.ts` | компоненты обязаны иметь текстовые статусы и имена |
| Домен: рейтинг подразделений по SLA не строится | AGENTS §5 | круговые рейтинги подразделений по SLA запрещены |

## 2. Цена Orbit (FACT, minified)

| Файл | Размер | Что будет с бюджетом |
|---|---|---|
| `dist/orbit.min.css` | **186 КБ** | demo: 238.6 → ≈ 425 КБ при бюджете 260 (перебор ≈ 165 КБ) |
| `dist/orbit.min.js` | **31 КБ** | app.js: 165.4 → ≈ 190–196 КБ при бюджете 180 (перебор ≈ 10–16 КБ) |

Иные варианты: `orbit-properties.css` (1.7 КБ) содержит только `@property` и не заменяет CSS; разбиения CSS на части для точечной загрузки проект не публикует.

## 3. Совместимость (FACT, спайк)

Отдельная страница с документированной разметкой (`<div class="gauge bigbang"><div class="gravity-spot"><div class="orbit-10"><o-progress …>`), запущенная локально и проверенная Playwright в трёх движках:

| Движок | Результат |
|---|---|
| chromium | датчик 260×260, shadow DOM + SVG отрисованы, `sin()`/container units/`@property` поддержаны, **0 ошибок** |
| firefox | то же, **0 ошибок** |
| webkit | то же, **0 ошибок** |

Вывод: браузерный риск для нашей матрицы e2e (chromium + firefox + webkit) **отсутствует**; CSS-фолбэк не нужен. Без поддержки тригонометрии Orbit сам скрывает систему и показывает сообщение через `.bigbang::before`.

## 4. Риск конфликта стилей (FACT)

- Глобальные селекторы Orbit **заскоплены**: `:where(.gravity-spot) :where(input,button,textarea,select)`, `:where(.gravity-spot *)`, `:where(.gravity-spot) :where(h1…h6)`.
- `:root` объявляет только `--o-*`: пересечений с нашими 158 токенами — **0**.
- Единственный «общий» селектор — `[class^=angle-]` (префикс, которого у нас нет).
- Итог: `orbit.min.css` можно подключать рядом с нашими стилями без правок существующих селекторов, но нужно переопределить палитру под наши токены тёмной и светлой темы (`--o-fill`, `--o-back-fill`, `--o-stroke`).

## 5. Где радиальные элементы дали бы пользу (данные есть, правила соблюдены)

| Идея | Данные | Ограничение |
|---|---|---|
| Кольцо фаз SLA на обзоре | `overview.sla` (ok/paused/overdue/none) | текстовая легенда обязательна |
| Индикатор загрузки очереди | `overview.attention.length` к `overview.kpi.active` | без рейтингов |
| Расход норматива SLA в карточке | `slaHoursLeft` + `SLA_PROFILES.resolveHours` | без домыслов при отсутствии норматива |
| Радиальный циферблат суток в хронологии | события дня (`Move.at`) | замена существующей шкалы — риск |
| Радиальное меню действий | — | демо только для чтения, ценности нет |

## 6. Варианты внедрения

| ID | Вариант | Что меняем | Цена | Оценка | Риск |
|---|---|---|---|---|---|
| **O1** | **Спайк-страница вне SPA** (рекомендую первым): отдельная HTML-страница с Orbit на реальных данных, без `demo/` и бюджета | 1 HTML + 2 файла Orbit (217 КБ) или CDN на отдельной странице | бюджет SPA не меняется | 0,25 дня | низкий |
| **O2** | Полная интеграция в SPA | `dependencies` + build (splitting или рост бюджета), `verify:demo`, `size-budget`, `build-web` (список файлов), вызовы `Orbit.refresh()` после перерисовки (`outerHTML`), маппинг тем, a11y, e2e, axe, аудит | app.js ≥ 190 КБ, demo ≈ 425 КБ, два бюджета поднимать | 2–3 дня + по 0,5 дня на экран | средний |
| **O3** | **Свой радиальный компонент** (рекомендую для продукта): SVG-кольцо в нашем стиле | новый `src/web/radial-*.ts` (~60–80 строк) + unit/e2e | зависимостей 0, бюджет почти не растёт (единицы КБ) | 0,5–1 день на компонент | низкий |
| **O4** | OrbitCSS (Flexbox-фреймворк) | — | — | — | **отклонить**: архивирован с 2023, релиз 2021 |

Мы уже рисуем SVG вручную: `src/web/git-svg.ts` (143 строки) и `gantt-grid.ts` — то есть O3 не требует нового инструмента, только тригонометрию и токены.

## 7. Рекомендация

1. **O1** — за полдня собрать спайк-страницу с двумя-тремя кольцами на реальных данных и посмотреть глазами. Это единственный способ понять, даёт ли Orbit заметно больше, чем наш SVG.
2. **O3** — основной путь продукта: собственное кольцо на наших токенах и правилах доступности, без зависимости и без роста бюджета.
3. **O2** — только если после O1 окажется, что нужны именно возможности Orbit (текст по дуге, радиальные меню, 3D-слои) и владелец готов поднять бюджеты и добавить рантайм-зависимость.
4. **O4** — не рассматривать.

## 8. Чек-лист, если выбран O2

- [ ] Решение владельца: поднять бюджеты (предложение: app.js 210 КБ, demo 480 КБ) или включить `splitting` в сборке.
- [ ] `bun add @zumer/orbit`; проверить, что lockfile и CI-install проходят.
- [ ] `build-web`: добавить `orbit.min.css` в список копируемых файлов и `index.html`; обновить тест списка файлов.
- [ ] После каждой перерисовки (`paintBody`, `paint`) вызывать `Orbit.refresh(root)`.
- [ ] Маппинг палитры: `--o-fill/--o-back-fill/--o-stroke` → наши токены тёмной и светлой темы.
- [ ] Доступность: `interactive` + `hit-width` + `role`/`aria-*`, текстовая легенда; прогнать axe.
- [ ] Тесты: unit на разметку, e2e на отрисовку, audit и снимки; `verify:demo` и `size:budget` обновить.
- [ ] Проверить, что `Orbit.refresh` не ломает существующие экраны и что бандл остаётся самодостаточным (внутренний код, без сети).
