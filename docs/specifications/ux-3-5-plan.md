## 2. Пакеты работ

### P1. Динамика дашборда → события периода (WP-5)

**Проблема:** дельты KPI не ведут в список событий; реестр работает по одному дню, новые URL-параметры запрещены.

**Варианты (нужно решение OD-5):**

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| **A (рекомендую)** | Переиспользовать существующий `period`: ссылка из динамики ведёт в `#incidents?...&period=<N>&at=<конец периода>`, реестр в этом режиме показывает **события за N дней** и явную подпись «События за N дней» | новых параметров нет, `period` уже разбирается роутером; семантика Flow явная | реестр получает второй режим (нужна аккуратная подпись и тесты) |
| B | Ссылка на последний день периода | просто | показывает срез дня, а не события периода — вводит в заблуждение |
| C | Отдельный экран диапазона в хронологии | чистая семантика | больше работы, меняет структуру разделов |

**Требования (для варианта A):** R-P1-1 режим включается только при явном `period=` в адресе; R-P1-2 список строится из событий (`Flow`), а не из остатка; R-P1-3 при нулевой базе ссылки нет; R-P1-4 подпись режима и обратный переход к срезу дня; R-P1-5 существующие фильтры и `at` сохраняются.

**Тесты:** unit — расчёт событий периода и отсутствие ссылки при нулевой базе; e2e — клик по дельте открывает список, подпись режима видна, возврат к срезу работает.

**Изменения:** `src/web/dashboard-html.ts`, `src/web/incidents*.ts`, `src/web/router.ts` (только ссылки), CSS, тесты.

### P2. История передач подразделению в карточке (C-1)

**Требование:** R-P2-1 список accountable-назначений по порядку `assignedAt`; R-P2-2 интервал «с … по …» или «по настоящее время»; R-P2-3 основание (`reason`) текстом; R-P2-4 автор скрыт (решение 3A); R-P2-5 исторический срез без управляющих действий.

**Тесты:** unit — рендер трёх случаев (закрытая передача, открытая, без основания); e2e — у героя видна история передач.

**Изменения:** новый `src/web/incident-transfers.ts`, `src/web/incident-html.ts`, CSS, тесты.

### P3. Унификация компонентов (этап 1 плана)

**Требование:** R-P3-1 публичные хелперы `statusBadge`, `priorityBadge`, `actionCard`, `emptyState`, `filterChip`, `sectionHeader` в `components.ts`; R-P3-2 все экраны используют их вместо локальной разметки; R-P3-3 внешний вид не меняется (сравнение вычисленных цветов до/после).

**Тесты:** unit — наличие и использование хелперов (проверка разметки); e2e — базовый снимок вычисленных цветов на 6 маршрутах.

### P5. Правдивый критерий зон нажатия в аудите

**Требование:** R-P5-1 критерий зависит от вьюпорта: 44 px mobile/portrait, 36 px tablet/desktop/wide; R-P5-2 элементы оболочки вне рабочей области не считаются нарушением; R-P5-3 в отчёте разделены «нарушения» и «справочные метрики».

**Тесты:** unit на функцию оценки зон; повторный `bun run audit` с обновлением снимков.
