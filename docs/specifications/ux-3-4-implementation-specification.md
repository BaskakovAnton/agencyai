## 1. Назначение и правила

Документ описывает весь остаток работ по интерфейсу так, чтобы исполнение начиналось без дополнительных уточнений. Порядок пакетов — по [interface-roadmap.md](../design/interface-roadmap.md).

Правила исполнения (закон проекта):

1. **Тесты сначала:** на каждый пакет пишется красный тест, затем реализация; сдаётся только на полностью зелёных прогонах.
2. **Домен не переписывается:** `src/core` и `src/data` меняются только там, где пакет это прямо требует (WP-4, WP-6, WP-8) и только вместе с unit-тестами.
3. **URL-контракт не расширяется:** используются существующие параметры `at`, `view`, `period`, `department`, `priority`, `sla`, `sort`, `q`, `node`, `review`; новые параметры не вводятся.
4. **Файлы ≤ 200 строк;** файл ближе к лимиту — выносим модуль до начала правок (WP-1: `incidents-html.ts` = 195 строк).
5. **Никаких выдуманных данных:** отсутствие значения показывается текстом («Нет данных», «Без ответственного», «Нет SLA»).
6. Язык интерфейса, документации и коммитов — русский; сообщения коммитов — `feat:`/`fix:`/`docs:`/`test:`/`chore:`.
7. После каждого пакета: `typecheck → bun test → bun run e2e → build:demo` → коммит → push → проверка CI, Pages и живой версии.

## 3. Пакеты работ

### WP-1. Компактные фильтры реестра на мобильном

**Цель:** поднять плотность списка: с 1 карточки на экран до 2–3.

| ID | Требование |
|---|---|
| R-WP1-1 | На ширине < 768 px свёрнутая панель фильтров ≤ **220 px** по высоте |
| R-WP1-2 | В свёрнутом виде доступны: поиск, представление, дата, «Сбросить» |
| R-WP1-3 | Остальные контролы (приоритет, SLA, узел, сортировка, подразделение) — в раскрываемом блоке «Параметры» с `aria-expanded`/`aria-controls` |
| R-WP1-4 | Изменение любого фильтра по-прежнему меняет URL (`pushState`) и сохраняется при back/forward/reload |
| R-WP1-5 | Состояние раскрытия — только UI-состояние, в URL не попадает |
| R-WP1-6 | Все контролы ≥ 44 px по высоте; горизонтального переполнения нет на 360/390/430 |
| R-WP1-7 | Модуль тулбара выделяется в `src/web/incidents-toolbar.ts`, `incidents-html.ts` остаётся ≤ 200 строк |

**Изменения:** `src/web/incidents-html.ts`, новый `src/web/incidents-toolbar.ts`, `src/web/screens.css`, `src/web/incidents-view.ts` (если нужен обработчик раскрытия), `e2e/mobile.spec.ts`.

**Тесты:** T-WP1-1…T-WP1-4 (см. план тестирования). **Риск:** средний (URL-поведение) → обязательный регресс `e2e/ux32.spec.ts`.

## 6. Порядок и гейты

1. Красный тест зафиксирован в отчёте пакета.
