## 1. Утверждённые продуктовые решения UX-3.3

| ID | Решение | Следствие |
|---|---|---|
| DEC-33-01 | Историческая атрибуция подразделений на существующей интервальной модели назначений: на дату среза действует назначение типа accountable, интервал которого покрывает конец дня среза | раздел 8: алгоритм departmentOn, изменения в реестре, колонке подразделения, разрезе обзора и карточке |
| DEC-33-02 | Мобильное представление реестра - карточки строк ниже 768 px; обязательные поля: номер и название, приоритет, текущий этап, подразделение, срок SLA, переход в карточку | раздел 5 |
| DEC-33-03 | Объём Design System: токенизация палитры и реестр компонентов; визуальный редизайн экранов не выполняется | раздел 9 |

Неизменяемые решения: DEC-01 (Completed - поток за период), DEC-03 (историческая очередь подтверждений), семантика view=unassigned (активные без ответственного), department=none как фильтр подразделения, различие view=overdue и sla=overdue, сохранение at при полном сбросе, чип даты только при явно выбранной исторической дате, название Просроченные (активные), отсутствие счётчиков подразделений.

## 2. Цели и границы

Цель: завершённый, согласованный и проверяемый UX текущего продукта - от мобильного реестра до исторической ответственности, без нового продукта и без изменения утверждённой предметной области.

Входит (6 блоков): A - мобильный реестр; B - интерактивные зоны хронологии; C - карточка обращения (передачи и блок Дальше); D - Dashboard (периоды и переходы); E - Design System; F - историческая атрибуция (F5).

Не входит (MUST NOT): изменение доменной модели и генератора данных; серверная часть и авторизация; вложения и документы (в модели отсутствуют); полный визуальный редизайн; пересмотр DEC-01 и DEC-03; изменение SLA-логики; новые KPI; сравнение периодов там, где база недостоверна.

## 4. Общие требования к состояниям

| Состояние | Требование |
|---|---|
| Обычное | данные из модели, без заглушек |
| Загрузка | MUST NOT вводиться: SPA без сети, данные детерминированы |
| Пустой результат | MUST различать причины: нет данных на дату, поиск, представление, подразделение, без ответственного, комбинация, дата вне окна |
| Ошибка данных | MUST единое состояние при недоступной орг-модели: Данные организации недоступны, таблица без колонок подразделения и ответственного |
| Недоступное действие | MUST отключённый вид с пояснением причины (историческая дата, роль), без ложного успеха |
| Длинный текст | MUST перенос, без горизонтальной прокрутки страницы |
| Много элементов | MUST прокрутка списка, пагинация не вводится; при 30+ строках производительность сохраняется |
| Мобильный экран | MUST отсутствие переполнения страницы, зоны касания >= 32 px |

## 5. Блок A - мобильный реестр (DEC-33-02)

A-1 Раскладка (MUST). Ниже 768 px строка таблицы заменяется карточкой строки, помеченной data-incident-card. Таблица MUST NOT отображаться, внутренняя горизонтальная прокрутка MUST NOT присутствовать.

A-2 Обязательные поля карточки строки (MUST):

| Поле | Источник | Отображение |
|---|---|---|
| Номер и название | row.id, row.title | первая строка, номер жирным |
| Приоритет | row.priority | бейдж с тоном и текстом, статус не передаётся только цветом |
| Текущий этап | row.nodeTitle | текстовая строка |
| Подразделение | row.departmentName или Нет данных | при исторической дате значение на дату (блок F) |
| Срок SLA | row.slaText, row.phase | бейдж: Просрочено, Риск, В срок, Нет SLA |
| Переход | hrefIncident(row.id, day) | вся карточка - ссылка, высота зоны >= 44 px |

A-3 Второстепенные данные (MAY, по раскрытию): ситуация, последнее событие, роль исполнителя, идентификатор узла. Раскрытие - кнопка Подробнее с aria-expanded; состояние раскрытия MUST NOT попадать в URL.

A-4 Фильтры на мобильном (MUST): селекты Представление и Подразделение в две колонки; поиск на всю ширину; чипы активных фильтров - горизонтальная прокрутка; кнопка снятия чипа >= 32 px; кнопка Сбросить доступна без раскрытия.

A-5 Планшет 768-1023 px (MUST): таблица сохраняется, скрываются только колонки Изменено и Карточка (переход по строке целиком), фильтры в две строки, чипы прокручиваются. Скрывать колонки Приоритет, Этап, Подразделение, SLA MUST NOT.

A-6 Пустые состояния (MUST): на мобильном действуют те же семь состояний, что на десктопе, каждое с одним целевым действием; состояние data-outside-window остаётся единственным носителем текста о границах окна.

A-7 Критерии приёмки блока A:

1. На 360, 375, 390 и 430 px отсутствует горизонтальное переполнение страницы и отсутствует элемент data-incidents-table.
2. Все шесть обязательных полей видны без раскрытия.
3. Зоны касания всех интерактивных элементов >= 32 px.
4. Переход в карточку работает по тапу на любую часть карточки строки.
5. Back возвращает в список с сохранёнными фильтрами и датой.
6. На 768 и 1024 px видны колонки Приоритет, Этап, Подразделение, SLA.

## 6. Блок B - интерактивные зоны хронологии

B-1 (MUST): все интерактивные элементы экрана хронологии имеют область не менее 32 x 32 px, включая маркеры событий, дни шкалы и переключатели.
B-2 (SHOULD): визуальный размер мелких маркеров сохраняется, увеличивается только область нажатия через padding или прозрачную оболочку.
B-3 (MAY): на ширине менее 768 px Гант скрывается, остаётся вертикальный граф дня; легенды сокращаются до одной строки с раскрытием.
B-4 Критерий приёмки: на 390 px количество интерактивных элементов с высотой или шириной менее 32 px равно нулю; выбор дня и узла синхронизирован с параметром at.

## 7. Блок C - карточка обращения

C-1 Блок Передачи подразделений (MUST, закрывает C-1 Discovery). Расположение: после блока текущего состояния, перед историей перемещений. Источник: назначения обращения типа accountable, отсортированные по assignedAt.

| Поле строки передачи | Источник | Пример |
|---|---|---|
| Подразделение | assignment.departmentId -> название из справочника | Жилищное хозяйство |
| Сотрудник | assignment.employeeId -> ФИО и должность | Иванов И. И. (специалист) |
| Интервал | assignedAt - endedAt (последнее назначение - по настоящее время) | 21.12.2025 - 22.12.2025 |
| Причина передачи | assignment.reason | Демо-переназначение по нагрузке |
| Результат | assignment.result | Передано подразделению DEP-CONTROL |

Требования: блок MUST NOT создавать данные, отсутствующие в модели; при одном назначении без передачи блок показывает текущую ответственность без слова передача; при отсутствии назначений MUST показываться Нет данных об ответственном.

C-2 Блок Дальше (MUST, закрывает C-2 Discovery). Показывает ближайшее ожидаемое действие и срок: на исторической дате - пояснение, что действия недоступны; на текущей - доступное действие по роли из availableOrgActions и срок SLA (row.slaText). Действия, отсутствующие в модели, MUST NOT предлагаться.

C-3 Разделение текущего и исторического (MUST): блоки текущего состояния и истории визуально разделены заголовками; исторический режим помечается существующим индикатором UX-3.2.2.

C-4 Критерии приёмки блока C:

1. На карточке обращения с состоявшейся передачей видны обе стороны передачи, интервал, причина и результат.
2. На карточке без передач блок не содержит слова передача и не пустует.
3. Блок Дальше показывает действие и срок на текущей дате и пояснение на исторической.
4. Ни один элемент карточки не предлагает операцию, отсутствующую в доменной модели.

## 8. Блок D - Executive Dashboard

D-1 Периоды (MUST): сохранить 7 и 30 дней, добавить Текущий месяц и произвольный период (даты с и по). Значения периода живут в URL (period=7|30|month|custom и params from, to) и восстанавливаются после reload, Back и Forward.

| Показатель | Источник | Тип | Переход |
|---|---|---|---|
| Активные обращения | snapshotOn.active | моментный | view=active |
| Требуют внимания | snapshotOn.attention | моментный | view=attention |
| На паузе | snapshotOn.paused | моментный | view=paused |
| Завершено за период | flow.finished | потоковый | нет (DEC-01) |
| Ждут подтверждения | snapshotOn.pendingReview | моментный | view=review |
| Распределение по подразделениям | departmentDistribution на дату | моментный | department=DEP-* (по правилу блока F) |
| Динамика за период | flowOf по дням периода | потоковый | MAY: ссылка в реестр с sla=overdue на дату конца периода (только если состав объясним) |

D-2 Подпись базы сравнения (MUST): дельта показывается с подписью базы, например К предыдущим 7 дням; при нулевой базе MUST выводиться Нет сравнения (правило UX-3).

D-3 Запреты (MUST NOT): новые KPI без источника; проценты улучшения без корректной базы; смешивание моментных и потоковых показателей в одной карточке; фиктивные данные.

D-4 Критерии приёмки блока D:

1. Четыре периода доступны и восстанавливаются из URL; месяц считается по календарю, произвольный - по включительным границам.
2. Каждая карточка моментного состояния открывает реестр с соответствующим view, и число строк равно значению карточки на ту же дату.
3. Подпись базы сравнения присутствует; при нулевой базе выводится Нет сравнения.
4. Карточка Завершено за период остаётся без перехода.
5. В блоке динамики нет данных, не подтверждённых моделью.

## 9. Блок E - Design System (DEC-33-03)

E-1 Токены (MUST): палитра, отступы, радиусы, тени, размеры шрифтов и высоты контролов задаются в src/web/tokens.css. Литералы цвета в остальных CSS-файлах MUST сокращаться; допускаются только токены или прозрачность. Цель блока - снизить текущие 122 литеральных цвета до значений, определённых токенами (фактическое число фиксируется в отчёте этапа).

| Группа токенов | Состав (MUST) |
|---|---|
| Цвет | фон, поверхность, поверхность-мягкая, граница, текст, текст-приглушённый, акцент, предупреждение, опасность, успех |
| Типографика | 4 размера текста, 3 размера заголовков, межстрочный интервал, вес |
| Пространство | 4-шаговая шкала отступов |
| Форма | 3 радиуса, 2 тени, высоты контролов 32 и 36 px |

E-2 Реестр компонентов (MUST): в спецификации и отчёте фиксируется таблица компонентов с единственным каноническим использованием: кнопка, ссылка-панель, селект, поле поиска, бейдж статуса, бейдж SLA, карточка-панель, чип фильтра, пустое состояние, счётчик результатов, индикатор исторического режима.

E-3 Правила (MUST NOT): разные стили одной функции; разные цветовые обозначения одного статуса; локальные CSS-исключения без указания причины; повторное использование класса одного экрана на другом (случай chip/chips в UX-3.2.4).

E-4 Визуальная идентичность (MUST): текущая палитра и типографика сохраняются, изменения допускаются только как следствие токенизации.

## 10. Блок F - историческая атрибуция подразделений (DEC-33-01, F5)

F-1 Алгоритм departmentOn(incidentId, day) (MUST, единственная реализация, общая для реестра, колонки, обзора и карточки):

1. Взять назначения обращения, у которых assignmentType = accountable и status = active (либо завершённые, если активных нет).
2. Отобрать те, у которых assignedAt <= конец дня day и (endedAt отсутствует или endedAt > начало дня day).
3. Если таких несколько - выбрать назначение с наибольшим assignedAt (последнее начавшееся); при равенстве - с наибольшим endedAt.
4. Если подходящих нет - взять последнее назначение с assignedAt <= конец дня day (ответственный был определён ранее и не заменён).
5. Если назначений нет вовсе - результат none (без ответственного).

F-2 Следствия (MUST):

| Поверхность | Изменение |
|---|---|
| Фильтр реестра department | Сравнение с результатом departmentOn на дату среза вместо текущего accountableOf |
| Колонка Подразделение в реестре | Показывает подразделение на дату среза; при текущей дате результат совпадает с прежним поведением |
| Разрез подразделений в обзоре | distribution строится по departmentOn на дату среза |
| Блок Передачи в карточке | Использует те же назначения; правило выбора совпадает с F-1 |
| department=none | Семантика не меняется: отсутствие назначения по правилу F-1 |
| Пояснение F5 (UX-3.2.4) | Убирается, так как ограничение снято; в историческом режиме остаётся индикатор исторической даты |

F-3 Инварианты (MUST): счётчик очереди подтверждений (DEC-03) не изменяется; view=unassigned остаётся множеством активных без ответственного по активному назначению; на текущей дате результаты фильтра и разреза совпадают с прежними (регрессионная проверка на 25 днях окна и на текущем дне).

F-4 Данные (FACT): назначения содержат assignedAt, endedAt, departmentId, employeeId, assignmentType, status, reason, result; в демо-данных 7 состоявшихся передач. Фиктивная история MUST NOT создаваться: если интервал отсутствует, применяется F-1 пункт 4, и это фиксируется тестом.

F-5 Критерии приёмки блока F:

1. На дату между двумя передачами фильтр по подразделению возвращает прежнее подразделение, на дату после передачи - новое.
2. Сумма по подразделениям и none равна общему числу обращений на дату (полное разбиение).
3. На 25 днях окна состав соответствует независимому расчёту по F-1.
4. На текущем дне результаты не отличаются от поведения до этапа (регрессия).
5. Карточка показывает интервалы и причины передач, совпадающие с фильтром.
## 11. Блок G - доступность

G-1 (MUST): зоны касания >= 32 px (мобильные карточки и кнопки снятия чипов >= 32, карточка строки >= 44).
G-2 (MUST): фокус виден на всех интерактивных элементах (существующий outline 2px сохраняется).
G-3 (MUST): статусы не передаются только цветом - у бейджей есть текст.
G-4 (MUST): счётчик результатов получает aria-live=polite, чтобы изменение количества объявлялось.
G-5 (MUST): кнопки снятия чипов имеют aria-label с названием фильтра; селекты имеют label.
G-6 (SHOULD): контраст текста к фону не ниже 4.5:1 для основного текста и 3:1 для крупного; проверка инструментальная (axe-core) в блоке QA.
G-7 (MUST NOT): перекрытие интерактивных зон, вложенные интерактивные элементы, скрытие критичных данных за hover.
G-8 UNKNOWN до QA: полное соответствие WCAG 2.2 AA не заявляется до инструментальной проверки.

## 14. Критерии приёмки UX-3.3

1. Мобильный реестр: на 360, 375, 390 и 430 px нет таблицы и нет переполнения страницы; шесть обязательных полей видны; зоны касания >= 32 px.
2. Планшет: на 768 и 1024 px сохранены колонки Приоритет, Этап, Подразделение, SLA; скрыты только Изменено и Карточка.
3. Хронология: на 390 px нет интерактивных элементов менее 32 px.
4. Карточка: блок Передачи показывает интервалы, причины и результаты из модели; блок Дальше показывает действие и срок.
5. Dashboard: доступны 4 периода; каждая карточка состояния связана со списком; подпись базы сравнения присутствует; при нулевой базе выводится Нет сравнения.
6. Историческая атрибуция: фильтр, колонка, разрез обзора и карточка используют единый departmentOn; на 25 днях окна состав соответствует независимому расчёту; полное разбиение по подразделениям сохраняется.
7. Design System: палитра токенизирована, литеральные цвета сокращены, реестр компонентов заполнен.
8. Доступность: зоны касания, видимый фокус, aria-live счётчика, статусы текстом и цветом; инструментальная проверка контраста выполнена.
9. Состояния: семь пустых состояний, состояние недоступной орг-модели, отключённые действия с пояснением.
10. Навигация: пять сценариев проходят, Back и Forward восстанавливают интерфейс, смена ширины не сбрасывает состояние.
11. Регрессии: DEC-01, DEC-03, view=unassigned, department=none, view=overdue и sla=overdue, сохранение at, чип даты - без изменений.
12. Качество: TypeScript strict, unit и e2e зелёные, файлы src/web не более 200 строк, запрещённые конструкции отсутствуют.
13. Документация: отчёты реализации, QA и остаточный backlog сформированы.
14. Публикация: только по отдельному разрешению владельца продукта.

## 17. Ограничения, UNKNOWN и открытые вопросы

Ограничения: серверной части нет, состояние загрузки и ошибок сети не существует; вложений и документов в модели нет; мобильная проверка выполняется эмуляцией viewport (физические устройства не доступны в этом окружении); сравнение периодов ограничено случаями с ненулевой базой.

UNKNOWN: контраст до инструментальной проверки; поведение на физических устройствах; необходимость показывать автора передачи (assignedByUserId есть в модели, но требование не подтверждено).

Открытые вопросы, требующие решения владельца только при реализации: (1) показывать ли автора передачи в блоке Передачи; (2) нужен ли произвольный период в URL отдельными параметрами from и to или одним значением. Оба вопроса не меняют бизнес-семантику и не блокируют старт реализации.
