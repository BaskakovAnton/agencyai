## 2. Пакеты работ

### C1. CI-гейт синхронности demo

**Требование:** R-C1-1 скрипт `scripts/verify-demo-sync.ts` собирает проект во временную папку и сравнивает SHA-256 файлов с закоммиченным `demo/`; R-C1-2 шаг добавлен в CI после `bun test`; R-C1-3 при расхождении сборка падает с понятным сообщением; R-C1-4 локально доступен `bun run verify:demo`.

**Зачем:** именно это расхождение уже приводило к устаревшему опубликованному `app.js`.

### C2. Чистка мёртвого CSS

**Требование:** R-C2-1 удалить правила для классов, которых нет в разметке (`.incidents-table` и подобные); R-C2-2 unit-тест «в CSS нет правил для неизвестных классов экранов» (эвристика по списку известных); R-C2-3 внешний вид не меняется (сравнение вычисленных цветов и размеров до/после).

### C3. Покрытие тестами

**Требование:** R-C3-1 шаг `bun run coverage:gate` в CI (lcov, отдельная временная папка); R-C3-2 порог для **доменного слоя** `src/core` + `src/data`: строки ≥ **92%**, функции ≥ **88%**; R-C3-3 дописать тесты для модулей ниже порога.

**Уточнение (FACT):** общий показатель `bun test --coverage` — 86.10% строк / 89.28% функций, потому что DOM-модули (`*-view.ts`, `*-interactions.ts`) юнит-тестами не покрываются: они проверяются Playwright-набором (156 сценариев). Поэтому порог ставится на домен, а общий показатель остаётся справочным. После добавления тестов домен даёт **99.35% строк / 98.47% функций**.

### C4. Расширение axe-набора

**Требование:** R-C4-1 добавить состояния: пустой реестр (дата без заявок), пустая хронология, режим «события периода», тёмная тема; R-C4-2 по-прежнему 0 нарушений critical/serious; R-C4-3 клавиатурный обход для новых состояний.

### C5. Довести унификацию компонентов

**Требование:** R-C5-1 заменить локальные заголовки на `renderSectionHeader`; R-C5-2 проверить, что бейджи и пустые состояния не собираются вручную (`grep`-тест); R-C5-3 разметка не меняется.

### C6. Правило документов

**Требование:** R-C6-1 зафиксировать в `AGENTS.md` §7 и в roadmap: в Git идут спецификации и релизные отчёты, черновики discovery/review остаются локальными; R-C6-2 список локальных документов в roadmap, чтобы они не «висели» как непонятный остаток.

### C9. Чек-лист пиксельной приёмки

**Требование:** R-C9-1 документ с 45 снимками, разбитыми по экранам и вьюпортам, с местом для замечаний владельца; R-C9-2 после замечаний — пакет исправлений с тестами.
